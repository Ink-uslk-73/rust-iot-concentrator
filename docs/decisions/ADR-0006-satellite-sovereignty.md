# ADR-0006: Суверенитет сателлитов

**Статус:** принято
**Дата:** 2026-10-29

## Контекст

Концентратор — двухпроцессорная система (2P AMD EPYC, xGMI, NUMA), где живут
данные и оркестрация. Вокруг — три сателлита (PLATE-A/B/C), которые живут
**почти автономно**, как протектораты: свои драйверы, СУБД, протоколы, свои
законы и правила, пока не понадобится заимствовать ресурсы у митрополии.

## Решение (метафора → архитектура)

| Метафора | Архитектура |
|---|---|
| Митрополия | Концентратор (2P EPYC, xGMI, NUMA): данные, Bus, Supervisor |
| Протектораты | Сателлиты PLATE-A/B/C: почти автономные «чёрные ящики» |
| Экспорт | Единственный канал сателлит → митрополия: данные, сигналы, телеметрия |
| Импорт ресурсов | Только по запросу («когда приспичит»): CPU/память/NUMA/БД |
| Валюта | **Данные** |
| Сеньор и вассалы | Концентратор повелевает сателлитами (Bus: Command/ModeChange/Shutdown) |
| Основное занятие | **Управлять** |

## Сателлиты

| Сателлит | Домен | Роль |
|---|---|---|
| **PLATE-A (Hard)** | AIG-502 | Управляет сенсорными сетями: **31 сенсор на порт**, связь со всеми сетями и митрополией |
| **PLATE-B (Soft)** | TODO | Умный, автономный. Живёт своей жизнью, пока не обнаружит, что нужно «дружить» за пределами территории — тогда идёт к PLATE-C |
| **PLATE-C (Life)** | несущая + ASUS + FPGA | **МИД**: думает про экспорт/импорт, **валюта — данные**, имеет **собственный банк данных в СУБД** «на всякий случай» |

## Принципы

1. **Автономия**: сателлит сам решает, как управлять своими сетями/данными.
2. **Экспорт — единственный обязательный канал**: данные/сигналы/телеметрия в митрополию.
3. **Импорт — только по запросу**: ресурсы митрополии (CPU/память/NUMA/БД) — когда своих не хватает.
4. **Валюта — данные**: обмен между сателлитами и митрополией — только данными.
5. **Горизонтальный обмен**: PLATE-B ↔ PLATE-C — «дружба» за пределами своей территории.
6. **Сеньор повелевает**: концентратор через Bus (`Command`, `ModeChange`, `Shutdown`) управляет сателлитами.
7. **Dew-принципы**: сателлит автономен (independence) и синхронизируется с митрополией только когда нужно (collaboration). См. `Dew Computing` в глоссарии.

## Что НЕ входит

- **PCIe P2P / ACS / xGMI** — системотехника концентратора, не сателлита.
- **SATA** — исключён.
- **Modbus-трансиверы на несущей** — не нужны (AIG-502 PLATE-A делает программно).

## Последствия

- `SatelliteId { A, B, C }` — **ключ** к конфигурации: `config/satellite/<id>.toml` (драйверы, СУБД, протоколы).
- `PeerAgent` живёт **на сателлите**: отправляет только экспорт, принимает команды сеньора.
- Store-forward — на случай, если канал в митрополию лёг: экспорт не теряется.
- Каждый сателлит — своя доработка ПО (драйверы, СУБД, протоколы).
