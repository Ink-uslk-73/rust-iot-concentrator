# ADR-0016: Роли IoT-концентратора (4 типа)

**Статус:** accepted
**Дата:** 2026-10-31

## Контекст

Термин «концентратор» перегружен. В IoT/телеком — 4 разных роли:

1. **Аппаратный IoT-шлюз** — преобразование протоколов, edge, безопасность (MG-E3, Moxa ThingsPro).
2. **Сетевой коммутатор / DSLAM** — операторский класс, агрегация трафика, доступ.
3. **Инфраструктура сотовых сетей** — NB-IoT base station, оператор.
4. **Программно-аппаратный комплекс** — EPYC, 10–1000 мс, интеграция всех ролей.

Нужно **зафиксировать**, что `frontier` = **4-й тип** (программно-аппаратный комплекс), а **не** 1/2/3.

## Решение

**`frontier`** — **программно-аппаратный комплекс** (4-й тип):
- **2× EPYC 7002**, 24× HDD, 3 expansion plates (A/B/C);
- **HARD/SOFT/LIFE** (10/100/1000 мс), **Frontier** (7 состояний);
- **DLMS + NB-IoT + LTE-M + edge-шлюз (PLATE-B) + Router WI** (ADR-0015);
- **API/UI** (`Frontier Cockpit`, `http://127.0.0.1:1967/`);
- **Collector** (SNMP/NetFlow/Syslog, ADR-0010).

**Не** 1-й тип (аппаратный шлюз) — **нет** готового «коробочного» продукта, есть **программный** + **несущая**.
**Не** 2-й тип (DSLAM) — **нет** операторского доступа, есть **IoT-агрегация**.
**Не** 3-й тип (NB-IoT BS) — **нет** собственной сотовой инфраструктуры, используем **оператора** (SIM7080G, PLATE-B).

## Обоснование

- **4-й тип** — **интеграция** всех ролей (edge + агрегация + протоколы + API);
- **ЭПИК** — **производительность** для **10 мс** (HARD);
- **PLATE-A/B/C** — **сателлиты** (митрополия/протектораты, ADR-0006);
- **Frontier** (7 состояний) — **аналитика** (Raw → Patterned).

## Что НЕ входит

- **1-й тип** (аппаратный шлюз) — **нет** «коробки», есть **несущая** + **ATX**;
- **2-й тип** (DSLAM) — **нет** операторского доступа;
- **3-й тип** (NB-IoT BS) — **нет** сотовой инфраструктуры (используем **оператора**).
