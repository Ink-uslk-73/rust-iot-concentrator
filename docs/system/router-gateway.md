# Программные роутер и шлюз по доменам

**Статус:** accepted
**Связанные:** [ADR-0004](../decisions/ADR-0004-router-gateway-domains.md)

Домены сателлита PLATE-A/B/C. P2P не используется (P2P у концентратора).

## PLATE-A (Hard) = Moxa AIG-502

- **Готовое устройство** (не на несущей, отдельный модуль в шасси 4U-19).
- **Intel Core i7**, edge computing.
- **Modbus RTU/ASCII/TCP клиент**: функции 1, 2, 3, 4, 5, 6, 15, 16, 23.
- До **31 ведомого** на последовательный порт.
- **Программная** реализация протоколов (без внешних трансиверов на несущей).
- Интеграция Modbus в облако/озеро данных.
- Роль: **Hard-домен**, роутер Modbus RTU/ASCII/TCP.

## Relay / Smart host

- CORE — **smart host** для uplink: сателлит отдаёт данные в CORE, CORE решает, куда (MQTT/HTTP/OPC UA).
- **Не open relay**: аутентификация обязательна (mTLS/токены).
- Satellite-Raw → CORE-Raw по PCIe P2P — это **relay** (пересылка без изменения).
## Real (transit) роутер и безопасность

- **PLATE-C (LIFE)** — transit-роутер: пропускает трафик к облакам/озёрам, не терминирует без аутентификации.
- **CORE** — smart host для uplink (не open relay).
- **Туннели**: mTLS, WireGuard/IPsec — к «своим» (CORE, сателлиты, облако).
- **M.2 Key E (Wi-Fi)**: WRX90E-SAGE SE — опциональный модуль Wi-Fi 6/6E (локальная меш-сеть, резервный выход).
## MAN (Metropolitan Area Network) — замыкание внутри территории

- **MAN** — сеть в пределах территории (ТОСЭР, ГОК, сортировочный, пиролиз): кабель + Wi-Fi.
- **Не выход в интернет**: трафик замыкается внутри, между концентраторами и сателлитами.
- **Режим**: только **Unicast P2P** (по одному, даже если списком).
- **Multicast / broadcast / anycast — не использовать**: риск broadcast-штормов, amplification, DDoS.
## Ёмкость MAN и синхронизация

- **MAN достаточен**: 10–12 концентраторов + сателлиты, кабель + Wi-Fi, локально.
- **Непрерывная синхронизация**: потоки (Redis/Raw/TimescaleDB) синхронизируются постоянно, не пачками.
- **Unicast P2P**: каждый поток — «один-к-одному» (даже если адресатов несколько — по одному).
- **Не multicast/broadcast/anycast**: риск DDoS, broadcast-штормов, amplification.
## Принципы (безопасность, Оккам)

- **Безопасность**: известное (Redis, TimescaleDB) — обновлять, аутентификация, mTLS; самописное (Raw, store & forward) — минимизировать, аудит, проверенные библиотеки.
- **Оккам**: не приумножать сущности — минимум middleware, проверенные компоненты, unicast P2P, гибрид CP/AP (не «одна СУБД на всё»).
