# Глоссарий

**Satellite (сателлит)**  одна из трёх плат (A/B/C), независимый
процесс-адаптер. Пишет ``alive.<PLATE>`` в Registry, чтобы heartbeat
мог подтвердить её живость.

**PLATE-A / PLATE-B / PLATE-C**  HARD (10 мс) / SOFT (100 мс) / LIFE (1000 мс).

**alive.<PLATE>**  gauge-метрика: timestamp (ms) последнего опроса,
пишется адаптером из его цикла ``start()``. Используется ``health_check``.

**heartbeat(name)**  отметка в ``SatelliteRegistry``: сателлит жив и
только что подтвердился. Вызывается из ``spawn_heartbeat`` при условии
``health_check == true``.

**health_check(&Registry, timeout_ms)**  проверка ``alive.<PLATE>`` на
свежесть. ``now - alive_ts < timeout_ms``  живой. Иначе  stale.

**Triple redundancy (тройное резервирование)**  3 сателлитные платы
(A/B/C) + AIG-502 (аппаратный резерв) + CORE (Redis hot-path + Raw CBOR +
TimescaleDB). Отказ любого слоя не роняет концентратор.

**AIG-502**  резервный Modbus TCP шлюз. Держит snapshot последней
телеметрии, включается при недоступности CORE.

**CORE: три уровня данных**:
- Redis  hot-path, TTL 60 с, O(1);
- Raw CBOR  бинарный лог без потерь (10 МБ сегменты, ротация 24 ч);
- TimescaleDB  агрегаты 1s/1m/1h, долговременное хранение.

**spawn_restartable(name, factory)**  задача с автоперезапуском:
``catch_unwind`` внутри spawn, при панике  backoff 1 с и повторный вызов
``factory()``. Для доменов с уникальными ресурсами (mpsc::Receiver) 
не применять, только внутренний reconnect-loop.

**PublishFn**  ``Arc<dyn Fn(Priority, f64, &str) + Send + Sync>``,
адаптер пушит телеметрию в Bus.

**Язык проекта**  русский (документация, комментарии, commit messages).
Код (имена типов/функций)  английский.
**R&D**  research & development. Спецификации могут меняться; контракты (интерфейсы, протоколы, тайминги) фиксируются раньше реализации. Эмуляторы (AIG-502, умный дом, каналы)  штатная часть R&D, не заглушки навсегда.

**QPI/UPI/Infinity Fabric**  межпроцессорная шина (2 сокета, когерентная память). Не для периферии.

**PCIe P2P (peer-to-peer DMA)**  прямой обмен данными между сателлитами (и с CORE) по PCIe, без участия CPU концентратора. Требует поддержки root complex (ACS, IOMMU, BIOS).

**Трёхуровневое питание сателлита**  свой БП (основной) -> PCIe (резерв) -> ИБП (последний рубеж).

**Четыре уровня данных**  Satellite-Raw (локально, store & forward) -> CORE-Raw (CBOR) -> Redis (hot-path) -> TimescaleDB (агрегаты). PCIe P2P  транспорт между Satellite-Raw и CORE-Raw.

**Сателлит**  отдельный компьютер в стойке (не плата, не процесс). Свой энергоисточник + ИБП. Автономная перезагрузка, смена ПО, диагностика. Пишет Raw локально при перегрузке/сбое концентратора (store & forward).

**Store & forward**  сателлит пишет Raw локально, когда концентратор недоступен; досылает в CORE по PCIe P2P, когда концентратор оживает. Четвёртый уровень данных (Satellite-Raw -> CORE-Raw -> Redis -> TimescaleDB).

**alive.<PLATE>**  компьютер жив, а не процесс жив. Пишется агентом на сателлите; переживает перезагрузку сателлита (агент стартует заново) и сетевой/PCIe разрыв (alive стареет -> health_check = false).

**Triple redundancy (тройное резервирование)**  три функциональных слоя (PLATE-A HARD, PLATE-B SOFT, PLATE-C LIFE) + AIG-502 (аппаратный шлюз в HARD) + CORE (Redis/Raw/TimescaleDB). Роли плат не пересекаются, поэтому кворум не требуется: отказ одного слоя не роняет два других.

**Концентратор 4U**  габаритный бюджет стойки. Сателлиты  отдельные юниты (суммарно стойка 1016U). Требует расчёта тепла (1.73.3 кВт) и ИБП (35 кВА).
**Статус сателлитов (на 2026-10-29)**: PLATE-A (HARD)  полевые протоколы реальны (modbus), AIG-502  эмулятор (продакшен, железо не готово). PLATE-B (SOFT)  умный дом, эмуляторы, в разработке. PLATE-C (LIFE)  скоростные каналы, часть в разработке.

**xGMI**  межсокетный интерконнект AMD EPYC (часть Infinity Fabric). Cross-socket P2P DMA проходит через xGMI, а не через системную память. Genoa: ~96 GB/s, Turin: 192256 GB/s.

**ACS (Access Control Services)**  механизм PCIe, который принудительно направляет P2P-транзакции через root complex. Включённый ACS  главный тихий убийца P2P. Для bare-metal P2P ACS нужно отключить (или ACS-override).

**NPS (Nodes Per Socket)**  BIOS-настройка AMD EPYC: NPS1 (один NUMA-домен на сокет), NPS4 (четыре). Влияет на P2P-латентность: при NPS4 устройства на разных CCD могут оказаться в разных NUMA-доменах.

**Local vs Cross-socket P2P**  local (внутри одного сокета) быстрее; cross-socket (через xGMI) медленнее, но работает из коробки на 2P EPYC. Выигрыш cross-socket P2P  при больших объёмах; для мелких обменов может проиграть RAM-буферу.

**PeerLink (эмулятор)**  trait, имитирующий три режима: local P2P (низкая латентность), cross-socket P2P (выше латентность, ниже пропускная), fallback через RAM (ещё выше латентность). Позволяет тестировать store & forward до появления железа.

## Архитектура

- **Dew Computing** — парадигма (Yingwei Wang, 2015), дополняющая облачные
  вычисления: конечные устройства (ПК, смартфоны, IoT) предоставляют сервисы
  **независимо от облака** и синхронизируются с ним только при необходимости.
  Принципы: **Independence** (работа без интернета/облака) и **Collaboration**
  (автосинхронизация при связи). D2D: Wi-Fi Direct (~200 м), BLE Long Range
  (~100 м), Zigbee/Thread (mesh). Место в иерархии: Cloud → Fog → Edge → **Dew**
  (самый нижний слой, без промежуточной инфраструктуры). Примеры: Dropbox
  (SiD — Storage in Dew), Dew hotspots. Формализовано в IEEE, конференция DewCom.
  В проекте: сателлит **автономен** (independence) и синхронизируется с
  митрополией только когда нужно (**collaboration**) — это ровно `ADR-0006`.
- **Иерархия вычислений** — Cloud (облако) → Fog (туман) → Edge (край) → Dew (роса).
  В проекте: митрополия (Cloud) → сателлиты PLATE-A/B/C (Fog) → сенсоры (Edge) →
  автономная работа сателлита без митрополии (Dew).
